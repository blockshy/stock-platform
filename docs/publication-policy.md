# 公开资料与本地资料边界

## 可以进入 Git 的内容

- 项目源码、锁文件、无凭据的配置模板、数据库 Schema。
- 用户说明、通用安装步骤、测试方法、功能边界和部署规划。
- 不含运行数据的算法契约、合成测试数据、通用前端规范。
- 原项目来源、上游提交以及保留的第三方声明。

## 只保存在本地的内容

- `.local/private-docs/`：开发过程、操作交接、环境清单、服务器信息、现场测试证据和生产截图。
- `deployment/platform.local.json`：本机实际目录和完整运行配置。
- `.env` / `.env.local`、`secrets.json`、数据库客户端凭据、私钥和证书私钥。
- 数据库文件、逻辑备份、行情导出、模型、断点、日志、缓存、构建目录和虚拟环境。
- 含上述内容的历史 Git 备份。归档文件本身仍按私有资料管理。

私有文档只记录凭据文件的位置和用途，不复制密码、令牌或私钥正文。仓库外的本地数据库目录也不应通过子模块、软链接或归档文件间接发布。

## 提交前检查

```powershell
# 查看本次真正将提交的文件和内容，不能只看工作区中的最终文件。
git diff --cached --stat
git diff --cached

# 规则应命中本地配置及私有目录；仅有忽略规则不代表旧历史已经清理。
git check-ignore -v deployment/platform.local.json .local/private-docs/README.md

# 已跟踪但后来被忽略的文件也需要处理，不能用 .gitignore 掩盖。
git ls-files -ci --exclude-standard
```

发布前同时检查提交历史、作者邮箱、配置中的默认值、截图、二进制文件和 Git 远端地址。扫描没有命中只是检查结果，不是“绝无敏感信息”的保证。

## 历史处理与备份

首次公开版本使用经过清理的独立根提交。原本地历史归档在私有目录中，不作为公共提交的祖先，也不推送私有分支、标签或备份引用。后续发布使用普通提交与 `git push origin main`，避免使用 `--mirror`、`--all` 或无审查的标签推送。

`.gitignore` 不能代替备份。仅本地资料应单独备份到受控位置；公共 GitHub 仓库不能用来恢复行情、模型、凭据或完整运行环境。
