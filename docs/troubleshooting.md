# 常见问题与排查

优先查看 `npm.cmd run status`、页面任务编号和对应配置的日志。日志、数据库快照、连接串和进程诊断可能含本地信息，分享前应脱敏。

## 页面打开了，但没有数据

1. 确认当前配置的后端已经启动，页面连接的是预期端口。
2. 在浏览器网络面板检查 `/api` 请求，区分连接失败、非 JSON 响应和业务错误。
3. 核对 `VITE_BACKEND`、`VITE_API_BASE`，以及页面是否缓存了旧 API 基址；修改构建变量后需要重新构建。
4. 确认数据库确实存在目标日期行情或已计算结果。空库、未采集和未预测都可能合法地返回空结果。

前端会在本地存储中记住成功连接的备用 API 基址，键名为 `stock.api.base`。切换环境后如仍连接旧地址，可只清除这一项，再刷新页面；不要为了排障清空全部浏览器数据。

## 任务看起来卡住了

| 现象 | 先检查什么 |
| --- | --- |
| 最近成功查询时间不更新 | 浏览器网络请求、后端可达性、状态接口错误 |
| 状态持续为运行中，成功数为 0 | 当前阶段是否为训练或准备；相关日志是否更新 |
| 总数或成功数变化很慢 | 阶段耗时、行情源延迟、CPU 和内存，不将结果计数等同进度百分比 |
| 查询超时后按钮恢复可点 | 先查是否已有同类运行记录，避免重复提交 |
| 明确显示失败 | 记录任务编号、阶段和脱敏错误，修复原因后再决定重试 |

浏览器轮询失败不等于后台任务失败。不要通过重启应用来验证任务是否存活；后端启动会处理残留运行状态，强制重启可能使真实执行与数据库记录不一致。也不要额外启动行情源登录探针干扰正在进行的采集。

## 概率榜单只有少量股票

先清空关键词、顶栏选股和其他筛选条件，核对基准日与周期。然后检查最后一次 `PREDICT` 或 `DAILY` 是否成功结束、是否使用了股票数量限制、合格股票池是否足够大。

新行情入库不会自动生成新预测。历史长度、ST、停牌、缺失比例、代码前缀及模型可用性都会影响实际覆盖。58 ETF 不在当前个股模型池中，因此不会随采集进入概率榜单。

迁移连接配置会改变模型版本；当前同日多版本结果选择需要专项核验。不要通过删除历史预测或改写版本号来掩盖选择问题，相关改造列入[远端部署规划](remote-deployment-plan.md)。

## 停止或构建被拒绝

停止命令会核验任务、流水线和进程身份；有活动任务或无法确认空闲时会保留服务。应先处理报告出的具体原因，不要删除进程记录或使用强制结束绕过检查。

构建会拒绝覆盖正在使用的新项目产物。生产与验收服务共用 JAR 和前端输出目录，两者都应在空闲时停止后再构建。

## 数据库身份不匹配

核对本地配置中的 MySQL 安装目录、端口、库名、`dataRoot` 以及 `mysql/my.ini` 的数据目录。启动器会拒绝连接到不属于配置的实例，这项保护不能用放宽检查来绕过。

`deployment/Setup-Database.ps1` 只核验既有独立实例，不会自动创建空库、初始化 MySQL 或重置账号。首次环境准备见[配置说明](configuration.md)。

## 离线测试缺依赖或版本不符

- Node.js 需要与当前基线的 24 主版本一致，前端依赖按锁文件安装。
- 概率契约要求 Python 3.10.11 和精确锁定依赖；系统 Python 可以存在，但不替代项目虚拟环境。
- Java 离线测试读取 `dataRoot/maven`，首次准备时应先联网下载依赖；离线失败后不要直接启动全套集成测试代替。
- 版本变更需要重新评估数值回归；`--fast` 或减少模拟路径会改变计算方式，不是保持结果不变的通用加速方案。

## 模型文件不存在

数据库模型登记和模型文件必须一起备份、一起迁移。先检查登记路径、产物根目录和文件摘要；有些登记可能仅包含元数据，不能单凭路径为空判定文件丢失。

`PROB_RUNTIME_ROOT` 只影响相对路径，已有 Windows 绝对路径不会自动转换为 Linux 路径。远端迁移必须建立经过核对的路径映射。

## 旧版模型预测不可用

旧版模型预测服务未包含在本工程中。`VITE_ENABLE_LEGACY_FORECAST=false` 会让页面明确提示该功能未接入。当前可使用的短期预测和 Python 概率预测是另外的功能入口。
