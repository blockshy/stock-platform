# 采集断点与 BaoStock 批量验证

## 实施状态与边界

方案 A 已进入验证阶段。仓库提供持久断点、安全暂停/继续、严格源响应校验和独立批量取样工具；这些代码需要显式安装断点表并更新后端后才生效。原运行服务不会因源码修改自动升级。

批量通道目前仅用于隔离取样，没有接管生产行情。完整性、复权价格及评分/预测重算未验收前不切换；方案 B 只在方案 A 的权限、覆盖、等效性或实际性能不能满足需求时继续验证。Python 引擎保持不变，Java 迁移暂时搁置。

## 已核对的源协议边界

在线样本已覆盖批量股票、ETF、历史逐股、完整因子与日历。此阶段的完整性和价格匹配仅是样本证据，不是全市场计算验收。实际样本、性能数值和机器运行记录仅存于本地私有文档。

- 响应尾部的 CRC 只有与原始响应头和正文重新计算一致才接受；未知尾段、错页、错证券、残缺列及重复记录仍拒绝。
- 停牌记录可能同时缺少成交量和成交额。仅 `tradestatus=0` 且两者均为空的已核实形态保留原空值；正常交易缺值、只空一列或空白污染均不能伪装成零成交。
- ETF 批量可能返回完整 18 列，附带个股估值与 ST 字段。源快照保留这些列供核验，现有 ETF 入库映射仍不赋予个股含义，也不纳入个股模型。
- 历史名单可能缺显示名称。独立审计入口保留空名称并严格检查代码及交易状态；生产证券名称更新仍使用原有严格入口。
- 非交易日仅依据完整官方日历跳过，不发送日线请求，不生成虚假的成功空行情。报告以 `skippedDates` 明确记录理由，离线工具会再次核对。
- 复权候选保留完整因子和乘法结果精度，再按现有入库规则处理。先保留六位小数可能改变最终四位价格，不能直接照搬示例舍入。

## 哪些数据可以跳过

- 原始行情按证券、市场、复权标记和精确日期判断已有记录，补齐区间内部缺口，不再仅比较最早/最新日期。
- 每次完整成功查询与行情入库使用同一数据库事务记录成功区间。失败或残缺响应不记成功；下一复权口径失败，不会丢掉前一口径已经提交的结果。
- 上游明确成功返回的历史空区间也保存，避免反复查询上市前空段。保留返回日期清单；清单内的行情后来丢失时仍需补采。
- 交易日历必须明确覆盖每个自然日。缺失日期不是休市，行情空行也不是停牌。
- 当天交易日尚无行情时，不把当天永久封存为空覆盖；历史成功部分保留，当天等待上游更新后重试。

**前/后复权不能无条件跳过。** 当前尚未验证稳定的因子版本，每个新任务或恢复轮次都重新核对复权的整个窗口；当前只有原始行情的已确认覆盖可以跨轮稳定复用。即使同一天，上游也可能更新复权基准，观察日不能当作版本证明。旧库复权行同样不能仅凭日期存在认定正确。后续只有因子事件和价格重建验收通过后，才改为按变化证券维护历史基准；这一步是方案 A 提速的重要前提。

## 安全暂停与继续

更新后的“数据抓取”页面在服务明确支持时显示固定起止日期、“安全暂停”和“继续采集”。填写固定起始日优先于回看天数，截止日留空则使用任务提交当天；日期与证券池随后保存在后端。

点击“安全暂停”只提出请求。当前上游查询和数据库事务结束后，状态才变为 `paused`；等待期间仍禁止新任务。继续会创建一条新的执行日志，沿用原固定日期、参数和证券池，跳过经过确认的原始行情成功区间，前/后复权仍重新核验。刷新网页、重开浏览器或改变表单不会更改已保存任务的范围。

进程异常退出会记为中断/失败，不能假装已安全暂停；已经提交的断点仍可用于继续。部分证券失败的任务可再次补缺，完整完成的任务不能重复点击继续。成功计数包括确认完整后跳过的证券，不等于本轮网络请求数。

页面同时显示“最近已确认区间”，用于观察两次证券计数刷新之间的真实提交进展。成功空区间同样属于已确认区间，不代表新增了行情行。名单仅在严格成功但为空时回溯日期，网络、业务或校验错误不再通过换日期扩大重试；失败证券也保留请求间隔。

旧版任务没有持久参数，不能自动猜测原请求或给正在运行的旧线程补装暂停功能。旧任务结束后，如需补缺，应按已核对的原固定日期和证券范围重新提交。定时采集目前仍使用原有流程，只新增与手动任务共享会话锁；它没有手动任务的持久恢复按钮。

## 独立验证流程

所有命令从项目根运行。首先执行完整离线检查：

```powershell
npm.cmd test

# 仅新增四张断点表，默认隔离验收库，不复制或修改生产行情。
.\deployment\Install-CrawlCheckpoint.ps1 -Profile verification

# 默认只读取任务/进程状态，保存 readiness.json，不登录数据源。
.\deployment\Test-BaoStockBatch.ps1
```

任务、流水线、原服务或行情连接仍在使用时，取样入口拒绝在线执行，不自动停止它们。等待所有现有工作结束，再通过正常入口停止后端；原服务未支持共享锁，停止空闲服务也是避免定时器在验证中途登录的前提。

取样前将 [计划示例](../tests/batch_validation/probe-plan.example.json)复制到 `.local`，核对日期与证券。示例只覆盖少量代表日和证券，正式计划还须补上已核验的 ST、停牌、除权及非交易日样本。日期全部使用已完成的过去日期，三年起点和 58 ETF 的实际覆盖不能靠示例名称保证。

```powershell
# 在应用空闲且没有进程使用构建产物时构建；默认会执行离线检查。
npm.cmd run build

# 显式启用单连接在线取样；不会启动 Spring、写入行情库或切换生产数据源。
.\deployment\Test-BaoStockBatch.ps1 -Online -PlanFile .local\batch-validation\probe-plan.json

# 只读比较快照：逐日证券集、代表股票/ETF原始字段及因子证据。
engines\probability\.venv\Scripts\python.exe tests\batch_validation\evaluate_probe.py `
  --capture .local\runtime\verification\batch-probe\capture-report.json `
  --output .local\runtime\verification\batch-probe\source-evaluation.json
```

取样结果逐请求原子保存，重跑时校验身份与摘要后复用成功的原始数据响应；损坏快照不静默覆盖。复权与因子每轮重新获取并标记独立采样身份，不能在同一天拼接不同执行轮次；跨午夜停止保存本次响应。缓存命中和真实请求耗时分别记录，不能用缓存读取时间冒充上游提速。

`CAPTURED_NOT_ACCEPTED` 只表示计划内响应已保存。离线适配报告最高为 `PARTIAL`，始终标明模型未重算、复权公式未验收、禁止切换。这些保护不能通过改报告状态绕过。

计划可设置 `historyFirst: true` 优先取得逐股基准，便于定位批量源差异。该选项只改变顺序，不跳过计划内检查；复权与因子仍使用本次独立采样身份。

## 补缺流水线

`Run-MarketPipeline.ps1` 负责跟踪已创建的固定范围任务，不再隐式构建、停止或重启应用。失败补采优先使用持久断点继续，写请求结果未知时停止等待核对，不自动重发。新旧执行日志可通过根任务编号关联。

安全暂停后，流水线记录暂停并退出，不能自行撤销用户暂停。可先在页面继续，再以同一逻辑任务的编号重启流水线；`-ContinuePaused` 只授权本次遇到的一次暂停继续。进入评分或预测后的流水线不会在重启时自动重放写任务。

本入口会在股票与可选 ETF 采集及覆盖核验后执行评分、短期预测和概率预测；这属于正常业务计算，不代表批量方案的 A/B 等效验收。纯采集验证不应启动该完整流水线。旧版没有断点的任务若要补采，须用 `-LegacyCrawlRequestPath` 提供明确核对过的固定请求，不能猜测原参数。

覆盖核验使用已保存的独立交易日历，要求请求范围内每个自然日都有明确状态；不能用已有行情推断休市。股票两种口径和 ETF 分别检查内部缺日、窗口最后一个交易日、非交易日多余行及无效价格，先保存 CSV 和汇总证据，再阻止不完整数据进入计算。较晚首日保留为上市时间待核对项，整段无行情不能直接当作新股通过。旧版完全没有独立日历时只返回兼容统计，明确标记 `strictValidated=false`。

## 切换必须通过的后续验收

1. 按独立名单和日历核对全窗口证券/日期集合，检查重复、漏页、字段、单位、精度、空值与源状态。股票与 ETF 分开验收。
2. 用原始价格和完整历史因子构造候选前/后复权，在同一观察日与逐股基准逐行比较；核对除权日前后及窗口前最后一个有效因子。不得把原始价格改标为前复权，也不能默认缺失因子为 1。
3. 准备相同的隔离 A/B 输入、历史 OOS、模型、配置和种子，实际重算评分、短期、概率、GA、策略和做 T。现有概率 `predict` 路径包含拟合，不等于只加载模型；未跑的训练/推理分支保持 `NOT_RUN`。
4. 分别比较首次三年补采、日常增量与中断续采的耗时、请求量、失败率和覆盖率。只有同范围、完整成功的任务才计算速度比。
5. 通过上述门槛后备份并受控切换，保留原通道回退。独立安装生产断点表也必须通过活动任务检查，不能在旧任务仍运行时执行。

详细比较器、数值门槛及隔离重放顺序见 [离线验收工具说明](../tests/batch_validation/README.md)和[功能等效性契约](functional-parity.md)。实际机器状态、样本、截图和运行报告仅保存在 `.local`，不提交公共仓库。
