# Python 概率引擎迁移到 Java：可行性评估

> 状态：仅评估，尚未启动迁移。本轮继续使用现有 Python 概率引擎；没有替换模型、缩减计算参数或改变预测结果口径。

## 结论

迁移在技术上可行，但它是一次需要数值等效验收的计算引擎重写，不能视为把 Python 语法改写成 Java。行情采集、Web API、评分、短期预测与部分策略计算已经由 Java 承担，主要待迁移对象是 `engines/probability/engine` 中的数据矩阵、特征、M1～M10 模型、样本外评估和概率任务编排。

建议当前保留 Python，先建立稳定的跨语言输入输出契约，再按“基础公式 → 特征 → 已训练模型推理 → 完整训练与评估”的顺序推进。每阶段通过隔离双跑后再决定是否切换，不进行一次性替换。

**迁移到 Java 不保证解决共享服务器的 CPU 或内存不足。** 当前 NumPy、SciPy 和 scikit-learn 已使用编译后的数值实现；Java 若采用大量对象或不同计算库，可能更慢或更占内存。是否收益足够，应比较同一数据和参数下的峰值内存、任务耗时、结果差异及维护成本。

## 迁移范围和难度

| 部分 | 当前职责 | 难度与主要等效风险 |
| --- | --- | --- |
| 配置、日志、任务与数据库 | 配置解析、进度、11 张概率表、批量写入、CLI 返回 | 中：Java 已有调度基础；仍需保留字段、事务边界、失败状态、脱敏和断点身份 |
| 数据加载与资格筛选 | 日期/证券矩阵、缺失值、ST、停牌、有效历史和股票池 | 中高：索引对齐、排序、补值顺序和逐预测日资格会改变后续全部计算 |
| 特征与标签 | 滚动指标、横截面排名、标准化、未来区间标签 | 高：窗口边界、最少样本、标准差自由度、并列排名、浮点精度及停牌掩码必须一致 |
| M1 条件概率与贝叶斯信号 | 时间衰减、信号组合、平滑与概率截断 | 中：公式容易移植，组合排序、裁剪与统计样本必须复现 |
| M2 逻辑回归 | 预处理、带时间间隔隔离的交叉验证、加权拟合 | 高：L-BFGS、正则化语义、截距、停止阈值与最优参数选择影响系数 |
| M3 马尔可夫 | 三状态转移、卡方检验、收缩及多步概率 | 中：统计检验边界、阈值相等归属、矩阵顺序和退化分支 |
| M4 GARCH / EWMA | Student-t 似然、约束拟合、诊断及失败回退 | 高：L-BFGS-B、分布函数、初始值、收敛与触边规则必须一同保留 |
| M5 条件期望 | 标准化收益的上下行条件均值 | 中低：分位裁剪、空样本和收益单位不能变化 |
| M6 分位数回归 | 自定义小批量 SGD、分位损失、列对齐 | 高：随机排列、批次顺序、float32/float64 转换与求和次序影响训练结果 |
| M7 路径模拟 | FHS 残差抽样、涨跌停裁剪及概率一致性调整 | 高：随机数流、分位数插值、共用随机样本和求根停止条件 |
| M8 VaR / CVaR | 从分布和样本计算尾部风险 | 中：尾部符号、阈值包含关系、分位插值与收益转换 |
| M9 EVT | 超阈值样本、广义帕累托极大似然拟合 | 高：拟合约束、阈值、退化回退与求解器行为 |
| M10 融合与校准 | 非负融合、Isotonic / Platt 校准、概率截断 | 高：只能使用合格 OOS，校准分段、拟合阈值与边界插值必须一致 |
| 评估与回测 | 结算、指标、Bootstrap、可靠性、方法选择与回测 | 中高：历史 OOS、日期排序、分块抽样、交易成本和并列处理均影响结果 |

难度评估针对当前实现，并不表示某个同名 Java 库可以直接替换。选型时应按能力核验：矩阵与基础统计、概率分布及尾部函数、约束优化、加权逻辑回归、单调回归、可复现随机数、列式数据和版本化模型序列化。本方案不预先锁定尚未做兼容性试验的库。

## 不能丢失的兼容边界

1. **任务接口**：保留现有 DAILY、PREPARE、TRAIN、PREDICT、WALKFORWARD、SETTLE、EVALUATE、BACKTEST 的语义。`--asof`、数量限制、断点、强制重跑和快速模式不能被混为一谈。Java Web 请求仍只负责提交与查询任务，不在请求线程内执行完整训练。
2. **数据口径**：股票池、复权、单位、历史资格、训练/预测日期边界和 58 ETF 隔离保持不变。不能用只复制行情的数据库代替包含历史 OOS 的完整输入快照。
3. **统计参数**：保持 500 日窗口、250 个有效历史日、1/3/5/10 日周期、现有 OOS 规模、模拟路径数、种子与所有模型配置。减少样本、路径或迭代次数属于另一个需求。
4. **数值语义**：明确 float32/float64 的转换点、NaN/Inf/空值处理、排序稳定性、分位插值、标准差自由度和收益变换。保持同一数字种子并不自动产生相同随机序列。
5. **持久化与状态**：保留 LIVE/OOS、PENDING/SETTLED/EXCLUDED、任务成功/失败及预测复合主键。失败不能因退出码或部分结果写入而被标成成功。
6. **历史版本**：当前有效数据库连接会影响模型版本哈希；同日榜单也有版本字符串选择问题。迁移必须显式区分实现版本并保留映射，不能改写旧预测版本来掩盖差异。

上述接口、Schema 与容差基线见 [功能等效性](functional-parity.md)及 `contracts/probability-engine.json`。迁移中发现原算法问题时，先单独记录和审查；不要在翻译过程中顺手修公式，导致无法区分迁移差异与算法改版。

## 旧模型和随机数如何处理

现有模型保存为 Python pickle，并带 JSON 元数据。Java 不能把它当作普通 JSON 模型直接加载；现有元数据也不总是完整推理状态，例如信号参数存在截断展示，融合元数据没有完整校准器状态。

建议先在可信原环境中设计一次性、只读的模型导出器，输出带版本、特征顺序、数据类型、数组维度和摘要的中立格式。导出必须包含完整信号表、预处理统计、系数、分位矩阵及校准器分段/系数，逐模型比较导出前后的 Python 推理，再对比 Java 推理。保留原 pickle 与旧引擎作回退，不在迁移中覆盖历史模型文件。

对于模拟、抽样和 Bootstrap，先用固定的随机样本数组验证纯计算逻辑，再验证随机数生成器与抽样算法。若希望保持同输入结果，需要复现实际位生成器、种子派生、抽样/排列方法和消费顺序；不能仅把相同种子传给 Java 的默认随机类。

## 分阶段实施建议

| 阶段 | 交付物 | 进入下一阶段的条件 |
| --- | --- | --- |
| 0：冻结基线 | 完整输入快照、配置、模型、版本、环境、排序与重复运行报告 | 确认现有实现自身的可复现范围；数据和历史 OOS 均固定 |
| 1：基础计算 | 公式、分布、统计、矩阵、随机样本和精度适配层 | 性质测试、极端值、空样本、阈值和固定探针一致 |
| 2：数据与特征 | 日期/证券矩阵、资格、特征和标签 | 每列逐元素比较，离散资格完全一致，不只比最终收益 |
| 3：推理影子运行 | 中立模型导出、Java 推理、任务执行适配 | 同模型同特征的预测、风险与榜单字段通过，不写生产结果 |
| 4：训练与评估 | M1～M10 训练、滚动 OOS、校准、结算和回测 | 同输入完成新旧双跑，模型选择、回退分支、输出差异逐项解释 |
| 5：容量与切换 | 故障恢复、限额、压测、备份和回退 | 完整目标工作负载满足容量与结果门槛后，才切换唯一生产写入端 |

可以在任务调度层引入统一执行接口，暂时同时支持 Python CLI 和 Java 计算工作进程。两种实现写入各自验收库或明确隔离的结果空间，不能并发覆盖同一版本的生产结果。是否最终合入 API JVM，需依据 CPU、堆、故障隔离和取消行为测量决定，不能为“只剩一个语言”牺牲服务稳定性。

## 验收门槛与停止条件

- 股票集合、交易日、标签、计数、周期、状态、排除原因、选中方法和模型回退分支应一致。
- 现有固定数值探针采用绝对容差 `1e-8`、相对容差 `1e-7`；持久化小数按现有 `1e-6` 契约检查。跨实现完整训练先测量基线并逐项解释差异，不能自动放宽这些门槛。
- 单独检查概率和排序临界值：数值差很小仍可能改变风险等级、可靠性等级、榜单顺序或策略选择，不能只看平均误差。
- 验证断点、取消、进程异常、部分成功、模型缺失、数据库暂时不可用等状态，不将恢复失败伪装为任务完成。
- 比较同样目标工作量的总耗时、峰值内存、CPU、数据库压力和前端响应；数据规模、并发、模型和参数必须相同。
- 任何硬门槛不满足时继续保留 Python 生产实现，Java 仅作隔离试验；保留原模型、配置、输入与运行证据以便回退。

本文件是后续决策依据，不是已经完成 Java 引擎的交付说明。当前用户操作与测试入口保持不变，见[用户手册](user-guide.md)和[测试说明](testing.md)。
