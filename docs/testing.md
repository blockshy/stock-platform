# 测试与验收

测试分为离线检查、隔离数据库验证和浏览器验收。离线通过能证明固定契约与测试样本符合预期，不能代替真实数据采集或全市场训练的完成证明。

## 依赖与执行环境

统一检查入口使用 Windows PowerShell 5.1，要求 JDK 21、Node.js 24、Maven，以及 `engines/probability/.venv` 中的 Python 3.10.11。概率契约还会检查 `requirements.lock.txt` 的精确依赖版本。

先按[配置说明](configuration.md)完成本地环境配置。Java 测试以 Maven 离线模式运行，使用 `dataRoot/maven` 缓存；首次安装时必须先准备对应依赖。缺少依赖不代表业务测试失败，也不能通过跳过检查来宣称完整验收通过。

## 离线自动检查

以下命令均在项目根目录执行：

```powershell
# 执行完整离线检查：前端、概率契约、Java 单元契约和部署脚本。
npm.cmd test

# 分别排查前端轮询、主题与请求重试行为，以及统一界面规则和部署脚本。
npm.cmd run test:web
npm.cmd run check:ui
npm.cmd run test:deployment
```

完整入口不启动应用、采集或训练，也不连接真实生产数据库。Java 检查显式排除需要真实 Spring/数据库环境的两个集成测试类；部署脚本测试使用内存替身和专属临时目录。

前端离线测试包含系统主题变化、跨标签同步、存储异常、图表交互保留、GET 总预算与 `Retry-After`、取消及写请求只发送一次。Java BaoStock 测试使用内存 Socket，验证连接清理、三次共享尝试、会话恢复、中断和成功分页不重发，不登录真实行情源。

报告保存在 `.local/runtime/verification/reports/offline-checks.json`，属于本地文件，不提交 Git。判断结果时同时检查进程退出码、报告生成时间和 `status`：

| 状态 | 含义 |
| --- | --- |
| `PASS` | 本次配置的完整离线步骤通过 |
| `FAIL` | 至少一个已执行步骤失败，后续步骤可能未运行 |
| `PARTIAL` | 显式跳过了部分检查，不能当作全平台通过 |

`tests/run_checks.ps1 -SkipJava` 仅适合已知并发构建等排障场景；它会产生 `PARTIAL`。修改算法基线、锁文件或统计参数来让失败测试变绿，不属于普通修复，应单独审查实际行为变化。

## 构建验证

```powershell
# 先核对任务状态；只有应用空闲且停止使用构建产物后，才能重新构建。
npm.cmd run status
npm.cmd stop

# 默认先执行完整离线验收，通过后再打包 Java 和前端。
npm.cmd run build
```

生产和验收配置共用源码及构建产物。如果验收应用也已启动，应先在任务空闲时停止验收应用，再构建。不要直接覆盖运行中的 JAR 或 `dist`。

## 隔离数据库验证

`verification` 必须使用独立库、仅获该库授权的独立账号、独立端口和运行目录；仅修改后端端口不能构成隔离。

```powershell
# 前提：已单独准备验收数据库、凭据、模型和固定数据快照。
.\scripts\platform.ps1 -Action Start -Profile verification

# 查看验收服务状态；不要把旧生产进程误当成验收进程。
.\scripts\platform.ps1 -Action Status -Profile verification

# 验收完成且无活动任务后停止验收应用。
.\scripts\platform.ps1 -Action Stop -Profile verification
```

仓库中的 `verify_probability_database.py`、`verify_readonly_api_parity.py`、`smoke_verification_prepare.py` 是受保护的迁移验收工具，不属于默认离线检查。它们包含特定的本地端口、库名、基准日或快照假设：使用前必须核对源码与目标快照，不能直接当成任意新机器的一键测试。

验证内容应包含：

- 逻辑快照的表、视图、记录计数与 OOS 状态完整；ETF 未混入个股源视图。
- 模型登记路径与实际文件一致，文件摘要匹配，Java 可以正确调用 Python。
- 使用相同数据快照、基准日、配置、依赖和种子对比已有结果；只固定日期不足以复现变化中的数据库。
- 离散字段、股票集合与计数完全一致；数值按 `contracts/probability-engine.json` 的明确容差比较。
- 不在测试中调用真实行情源登录、不重新训练生产模型、不自动更新期望基线。

跨操作系统的完整训练还需单独评估科学计算库与浮点差异，不能据离线样本通过承诺所有预测逐位一致。

## 浏览器验收

| 检查范围 | 预期结果 |
| --- | --- |
| 导航、深层 URL 刷新、返回按钮 | 页面正确打开，当前路由与标题一致 |
| 加载、空结果、错误与重试 | 状态真实且可辨，不将查询失败显示成任务成功 |
| 股票选择、搜索、排序与分页 | 筛选规则一致，清空筛选后恢复对应全集 |
| K 线、数值单位、涨跌颜色 | 图表不溢出，价格与百分比格式一致 |
| 采集和概率任务观察器 | 状态持续刷新，保留任务编号，重复提交受限 |
| 桌面与窄屏 | 主要操作可触达，表格可滚动，弹层不遮挡关键内容 |
| 浅色、暗色、跟随系统 | 手动选择、系统实时变化、刷新恢复和跨标签同步正常；数据与表单值保持不变 |
| 下拉框、日期框、提示层与弹窗 | 两种配色可读、焦点可见，箭头不压文字，手机端可关闭和滚动 |
| 图表切换主题 | 先调整缩放和图例，再切换主题；保留缩放范围与图例选择，坐标及提示文字可读 |
| 未来远端部署 | HTTPS、认证、同源 API、长任务轮询和未登录写接口拒绝分别验证 |

真实写操作只在隔离验收环境中执行。完整验收记录、截图、数据库摘要及主机信息放在被忽略的本地文档目录；公共仓库只保留通用方法。

建议以 1440px 和 390px 窗口逐页检查，再用 768px 抽查顶栏与表单换行。主题检查可通过浏览器开发工具模拟 `prefers-color-scheme`；接口故障应通过测试替身或浏览器拦截模拟，不能为验证重试而重复提交真实采集或训练任务。只有空态数据的模块应记录覆盖限制，不宣称已验证其完整计算流程。
